## 一、真题记录

### Q1. AXI 上三个非连续寄存器，每个都 R 再 W：`rwrwrw` 还是 `rrrwww` 效率高？为何？

- **出处**：AMBA / AXI 相关面试
- **原题**：AXI 三个**非连续**寄存器，每个都要先 Read 再 Write——按 `rwrwrw`（交错）还是 `rrrwww`（先读完再写）效率更高？为什么？
- **当场要点**（整理自口述）：
  - AXI 细节久未碰，记得不清晰。
  - **AHB**：基本没区别——半双工，要等 slave ready、这一笔 read 结束才能发下一笔，交错与否差别不大。
  - **AXI**：倾向 **`rrrwww` 更快**。
- **参考答 / 自评**：
  - 结论方向对：AXI 上通常 **`rrrwww`（或更能打满通道并行的发单顺序）优于严格交错的 `rwrwrw`**。
  - AHB「差不多」也说得通；若想更稳，可补一句「共享地址/数据相，本质串行，交错省不出读写并行」。
  - 加分：点出 **AXI 读写通道分离 + outstanding**，并提一句前提（同 ID 保序、Device、寄存器副作用等），见第二块。

## 二、盲区延伸

### 由 Q1 → 为何 AXI 上 `rrrwww` 往往更香

题眼：**非连续** → 做不成一笔 burst，是 **三笔独立读 + 三笔独立写**；比的是**发单顺序**能不能吃到 AXI 的通道并行。

| | AXI | AHB（经典） |
|--|-----|-------------|
| 通路 | 读 AR+R、写 AW+W+B，**通道分离**，可同时活跃 | 共享地址/数据相，一拍数据相基本一笔 |
| outstanding | 多笔 AR/AW 可挂起（受 ID、深度限制） | 地址相可与上一笔数据相流水，但无「读写两套并行通道」 |
| 本题直觉 | **先连续打满读侧，再打满写侧**（或读地址与写地址重叠发）更易吃带宽 | 六笔仍基本串在同一条路上，`rwrwrw` ≈ `rrrwww` |

**`rrrwww` 为何通常更好（口述版）**：

1. **读通道成组、写通道成组**：先连续发 `AR0–AR2`（若允许多 outstanding），R 回来后再发 `AW/W`；读地址握手与后续写通道不会被「每读一笔就插入一写」拆碎。  
2. **软件/CPU 的 `rwrwrw` 常隐式串行**：见下一节——`ldr; str; …` 若「等完成再发」或「同 ID 深度=1」，outstanding 永远凑不起来，六笔尾尾相接。  
3. **`rrrwww` 把依赖收成两段**：三段读可并行飞（不同 ID 或深度允许时）；三段写同理。交错则读→写→读 更容易被「同地址 RAW / 同 ID 保序 / 等 B 再继续」卡住。

波形直觉（示意，忽略具体拍数）：

```text
rrrwww（读 outstanding=3 时）:
  AR:  ███ ███ ███
  R :     ██    ██    ██
  AW:                 ███ ███ ███
  W/B:                  ……

rwrwrw（每笔等完成）:
  AR ██  R ██  AW/W/B ███  AR ██  R ██  …
  （读写交替，通道并行窗口更窄）
```

### 由 Q1 → Outstanding 展开（为何说「主动放弃」）

#### 1. Outstanding 是什么

一笔 AXI 事务从 **地址通道握手成功** 起算「已发出」，到 **读收到 `RLAST` / 写收到 `B`** 才算「完成」。

**Outstanding = 已发出、尚未完成的事务个数。**

协议允许（在 master/互联/slave 深度内）**前一笔还没完成，就再发下一笔 AR/AW**——这才叫「有 outstanding」。AHB 经典模型基本是一笔做完再下一笔，没有这套「多笔同时在飞」。

```text
时间 ──────────────────────────────────────────▶

有 outstanding（深度≥3 的读）:
  发 AR0 ──▶ 发 AR1 ──▶ 发 AR2 ──▶ … 等 R0/R1/R2
  │           │           │
  └─ 此时 outstanding 可到 3：三笔都在路上，slave/互联可并行处理

无 outstanding（等完成再发）:
  发 AR0 ──▶ 等 R0 完 ──▶ 发 AR1 ──▶ 等 R1 完 ──▶ …
  │              │
  └─ 任意时刻 outstanding ≤ 1，总线空窗变多
```

「深度」是硬件槽位：同一 master 端口上，同时允许挂几笔未完成事务（常还按读/写、按 ID 再拆）。深度=4 不代表你一定用满——**软件/CPU 发单节奏**可以只用到 1。

#### 2. 和 AxID 的关系（同 ID 为何像「放弃」）

AXI 规则（口述够用）：

| 规则 | 含义 |
|------|------|
| **同 ID** | 同方向事务必须按发单顺序完成（读：R 按 AR 序；写：W 跟 AW 序，B 按同 ID 序） |
| **不同 ID** | 完成顺序可交错；更易真正并行 |
| **很多 CPU/互联实现** | 「同一 ID 同时只允许 1 笔 outstanding」——同 ID ≈ **必须等前一笔完成才能再发** |

因此：六笔全打成同一个 `AxID`，哪怕协议纸面上允许流水，实现也可能把你收成 **outstanding≤1**。换不同 ID、或先攒同向再换批，才谈得上把深度用满。  
（成文见 [`01-spinlock-to-bus.md`](../05-bus-rtl/01-spinlock-to-bus.md) §11.2。）

#### 3. 为何 `ldr; str; ldr; str` 常等于主动放弃

分两层——**指令语义** 和 **总线发单**：

**（1）CPU / 程序顺序往往「做完这笔才做下笔」**

```text
ldr x0, [reg0]   // 读：一般要等数据进寄存器，流水线才继续用 x0
str x0, [reg0]   // 写：常等前面的读退休 / 满足序要求后再发（尤其 Device）
ldr x1, [reg1]
str x1, [reg1]
…
```

- 每个 `ldr` 在用返回值前，对软件可见就是「这笔读完成了」。  
- Device / 强序 / `DMB` 下，core 更不敢让后面的访存超过前面的。  
- 结果：LSU 侧经常是 **发 AR → 等 R →（再）发 AW → 等 B → 再发下一笔**，总线上 **outstanding 长期 ≤1**。

硬件明明可能支持 outstanding=4，你却「做完一笔再发下一笔」——槽位空着不用，所以叫 **主动放弃 outstanding**（不是协议禁止，是发单策略没用上）。

**（2）即便 core 能提前发，交错顺序也更难叠读**

假设允许「读未完成就发写」：

| 发单 | 总线上看见的 | outstanding 形态 |
|------|--------------|------------------|
| `rrrwww`：连发三个 `ldr` 再三个 `str` | `AR0,AR1,AR2` 可先堆满，再堆 `AW` | 读段 outstanding 可到 3；写段再起一波 |
| `rwrwrw`：严格交替 | `AR0 → … → AW0 → … → AR1 → …` | 读侧很难同时挂 2～3 笔；读写互相插队，空窗多 |

所以：**放弃 outstanding ≠ 只能 `rwrwrw` 才会发生**；`rrrwww` 若也「每个 ldr 等完再发下一个」，照样放弃。本题说 `rwrwrw`「常」放弃，是因为这种写法**最容易**让程序员/编译器/强序属性变成「一笔接一笔」。

#### 4. 一句话对照

| 说法 | 含义 |
|------|------|
| **有 outstanding** | 前一笔未完成就已发出后一笔；多笔同时在飞，吃通道与 slave 并行 |
| **主动放弃** | 能力有（深度>1），但发单选择等完成 / 同 ID 深度1 / 强序挡超前 → 实际 outstanding 一直≈1 |
| **和本题关系** | 要比出 `rrrwww` 的优势，前提是读批（或写批）真能把 outstanding 抬上去；否则两种顺序墙钟接近 |

面试补一句：**Outstanding 是「未完成计数」；效率差来自你有没有连续发地址。软件一笔一等，等于把 AXI 用成 AHB。**

#### 5. Outstanding 深度在哪里「设置」？

**不是** AXI 协议里某个全局寄存器叫 `OUTSTANDING_DEPTH`；也**不是**普通 `ldr/str` 软件能随手改的。  
深度是链路各段的 **硬件能力 / 配置参数**，整条路径取 **木桶最短板**：

```text
Master（CPU / DMA / 加速器）
    → 发出侧：我最多同时挂几笔？（读/写常分开计）
Interconnect / NIC / Crossbar
    → 入口缓冲、按端口/QoS 的 outstanding 上限
Slave（SRAM ctrl / DDRC / 外设桥）
    → 接受侧：我最多同时接受几笔未完成？
```

实际能飞起来的 outstanding ≈ **min(master 能发, 互联肯传, slave 能收)**。

| 层级 | 深度从哪来 | 谁定 / 哪里看 |
|------|------------|----------------|
| **CPU / 通用 master** | 微架构：LSU 未完成队列、store buffer、同 ID 策略 | **硅前 RTL/IP 参数** 或 TRM「max outstanding reads/writes」；应用软件通常**改不了** |
| **DMA / NPU / 自定义 AXI master** | IP 配置：`MAX_READ_REQ`、`MAX_WRITE`、通道 outstanding、描述符深度 | **设计时** IP 参数；部分 SoC **驱动可写寄存器**限流（看该 DMA TRM） |
| **互联（NIC-400 / CCI / 自研 matrix）** | 每 slave 口 acceptance、每 master 口 issuing | 互联 **configure / TRM**；有的带 QoS/outstanding 限幅寄存器 |
| **Slave** | `ACCEPTANCE` 能力、FIFO 深度 | Slave TRM / IP 参数；外设常很小（1～数笔） |

面试怎么答：

1. **深度是硬件槽位，多层各自有上限，生效的是最小值。**  
2. **CPU 访存**：看 core/互联 TRM，不是内核里 `echo 8 > outstanding`。  
3. **DMA/加速器**：最常见「能设」的地方——IP 参数或通道控制寄存器。  
4. **软件侧能做的**往往是：发单节奏（`rrrwww` vs 一笔一等）、内存属性/屏障、选对 master（走 DMA 而不是 CPU 抠寄存器墙钟）——**用满**已有深度，而不是凭空把深度改大。

和「主动放弃」对照：深度是**天花板**；`ldr` 一笔一等是**实际用量**。天花板在芯片/IP 里定好了，用量在发单行为里。

### 由 Q1 → AHB「没区别」怎么说完整

- 经典 AHB：**半双工式**共享总线，当前 data phase 结束（`HREADY`）才能真正推进下一笔；没有 AXI 那种「读数据通道与写地址通道同时忙」。  
- 地址相可与上一笔数据相重叠，对**连续同向**略有流水收益，但本题六笔单次、又夹杂方向切换，**交错 vs 先读后写，墙钟差通常远小于 AXI 场景**。  
- 面试一句：**AHB 瓶颈在串行 grant/数据相，不在「R/W 顺序挖并行」；AXI 才值得纠结顺序。**

### 由 Q1 → 答题前提与坑（避免把结论说死）

这些情况下「一律 `rrrwww`」要收口：

| 条件 | 影响 |
|------|------|
| **同 `AxID` 且实现 outstanding=1** | 同 ID 必须按序完成，读也批不成并行，收益变小 |
| **Device / 强序 / 非 bufferable** | CPU/互联可能禁止读超前、写合并，接近串行 |
| **寄存器副作用** | 如读清、写触发；顺序由功能决定，不能只为带宽重排（题设「每个都 R 再 W」若有依赖，可能必须 per-reg `rw`） |
| **写依赖读值** | 若 W 的 data 依赖**同一个**寄存器刚读出的值，该 reg 必须 `r→w`；仍可对其它 reg 做「先读批、再写批」：`r0 r1 r2 w0 w1 w2` |
| **互联/ slave 深度很小** | outstanding 挖不出，两种顺序接近 |

面试收束句：**协议上 AXI 读写可并行，所以批量同向（`rrrwww`）通常优于严格交错；最终还看 ID/序/属性与寄存器语义。**

## 小结

1. 题考的是 **AXI 通道分离 + outstanding**，不是寄存器本身。  
2. **非连续** → 无 burst，只能靠发单顺序挖并行 → 通常 **`rrrwww` > `rwrwrw`**。  
3. **AHB** 共享通路，两种顺序往往差不多；对比 AXI 说更有分。  
4. 补充前提：同 ID / Device / 副作用 / 读值依赖写，可能被迫局部保持 `rw` 序。  
5. 口述公式：AHB 串行差不多；AXI 先攒读再攒写，吃满 AR/R 与 AW/W/B。
