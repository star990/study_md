## 1. 软件顺序执行 vs 硬件并发存在

写 C 时，心智模型是 **一条指令接一条**：

```text
PC → 取指 → 译码 → 执行 → 写回 → 下一条 PC
```

即使多核，每个核内部仍是顺序（乱序执行是微架构优化，对程序员仍像顺序）。

RTL 描述的是 **已经铺好的电路**。没有「for 循环跑一遍」，而是：

| 软件 | 硬件（RTL） |
|------|-------------|
| 语句按顺序执行 | 所有 `assign` / 组合 `always` **同时**根据当前输入算输出 |
| 变量存于内存/寄存器，用时才读 | `reg` / 触发器 **一直**保持着值，时钟沿才更新 |
| `if` 只走一个分支 | 组合逻辑里 **各分支的电路都在**，选路器决定哪路有效 |
| 延时 `sleep(1)` 是软件行为 | 「等一拍」靠 **时钟** 和 **触发器**，不是 sleep |

**抓波时的直觉**：波形上同一 `posedge clk` 竖线处，很多信号一起变；变的是 **上一拍结束时组合逻辑算好的结果**，在本拍沿被 **锁进** 下一级触发器。

## 2. Verilog 描述的是什么

Verilog / SystemVerilog 是 **硬件描述语言（HDL）**，不是「让 CPU 逐行执行的程序」。

综合（synthesis）后大致变成：

```text
与门 / 或门 / 非门 / 多路选择器 / 加法器 …  （组合逻辑）
        +
D 触发器（DFF）/ 寄存器堆 / SRAM 控制器 …     （时序逻辑）
```

语法像 C，容易误导。记住：

- **不是在描述算法步骤**，是在描述 **连线 + 寄存器**。
- 仿真器可以按事件驱动跑（像程序），但 **综合后的硅/FPGA 是并行电路**。
- 开源 [tiny-riscv](https://github.com/liangkangnan/tinyriscv) 刻意用接近 C 的风格写 RTL，方便软件背景阅读——但思维仍要切到「电路」。

## 3. 两类电路：组合逻辑与时序逻辑

### 3.1 组合逻辑（Combinational）

- **无记忆**：输出只取决于 **当前** 输入。
- 理想情况下输入一变，输出跟着变（真实门延迟纳秒级，仿真里常忽略或用 `#delay`）。
- 例子：加法器、译码器、多路选择器、`a & b | c`。

### 3.2 时序逻辑（Sequential）

- **有记忆**：输出/状态在 **时钟沿**（通常上升沿）才更新。
- 更新前，输出保持上一拍的值。
- 例子：PC 寄存器、流水线级间寄存器、状态机当前状态。

```text
组合逻辑：  out = f(in)           // 当前 in → 当前 out（无 clk）
时序逻辑：  q   <= d @ posedge clk // 本拍沿把 d 锁进 q，中间 q 不变
```

**和软件对照**：组合逻辑像 **纯函数**；时序逻辑像 **只在 interrupt / 定时器 tick 里才 commit 的全局变量**。

## 4. 触发器：一拍只改一次状态

**触发器（Flip-Flop，常写 FF 或 DFF）** 是最基本的时序单元。最常用 **D 触发器**：

```text
        ┌─────┐
   D ──►│ DFF │──► Q
        │     │
  clk ─►│ clk │
        └─────┘
```

行为（同步、上升沿触发）：

1. `posedge clk` **之前**：`Q` 保持旧值，不管 `D` 怎么抖。
2. **上升沿那一刻**：把当时的 `D` 采样进 `Q`。
3. **沿之后到下一沿**：`Q` 稳定为新值（直到下一沿）。

Verilog 里典型写法：

```verilog
always @(posedge clk) begin
    q <= d;   // 非阻塞 <= ，表示「本拍沿锁存」
end
```

**为什么需要 FF？**

- 把「这一拍算出的结果」 **固定下来**，给下一拍用。
- 没有 FF，组合逻辑链会 **无限传播**，无法在离散时钟下工作。
- CPU 的 PC、通用寄存器堆的写端口、流水线寄存器，底层都是 FF（或 FF 阵列）。

**锁存器（Latch）**：电平触发（高/低电平期间透明），时序分析更别扭；同步设计里 **应尽量避免无意生成 Latch**（见 §9）。

## 5. 经典结构：FF → 组合逻辑 → FF

数字同步电路最常见的「一块」：

```text
        ┌───┐      ┌──────────────┐      ┌───┐
   i ──►│D1 │─Q1──►│  组合逻辑     │─────►│D2 │──► o
        │   │      │  (译码/ALU/…)  │      │   │
  clk ──┤   │      └──────────────┘      │   │
        └───┘                              └───┘
          ▲                                  ▲
          └──────────── clk ──────────────────┘
```

含义：

1. **第一级 FF（D1）**：在时钟沿把输入 `i`（或来自上一模块的信号）锁成 `Q1`。
2. **组合逻辑云**：用 `Q1`（及可能的其他当前输入） **立刻** 算出中间结果（仿真里同一 time step；硅上是传播延迟）。
3. **第二级 FF（D2）**：在 **下一个** 时钟沿，把组合逻辑输出锁成 `o`。

**一个时钟周期内**，组合逻辑必须 **算完并稳定**，第二级 FF 才能正确采样。这就是 §6 的时序约束来源。

读 tiny-riscv 或任意 CPU RTL 时，可以反复问：**这一拍锁存的是什么？中间组合块在算什么？下一拍锁存什么？**

## 6. 一拍能走多远：时序与频率

### 6.1 建立时间与保持时间（建立/保持）

FF 不是「沿上任意时刻采样都行」：

| 概念 | 含义 | 违反后果 |
|------|------|----------|
| **Setup time** | 沿 **前**，`D` 必须已稳定足够久 | 亚稳态 / 采错 |
| **Hold time** | 沿 **后**，`D` 还要保持稳定一小段时间 | 亚稳态 / 采错 |

工具链用 **SDC / 约束** 和 **STA（静态时序分析）** 检查：所有 `FF→组合→FF` 路径是否在一拍内满足 setup/hold。

### 6.2 关键路径

**最长** 的那条组合逻辑链决定最高频率：

```text
T_clk  ≥  T_cq  +  T_comb_max  +  T_setup
         ↑          ↑              ↑
      第一级FF    组合逻辑        第二级FF
      时钟→Q      最大延迟        建立时间
```

- 组合逻辑 **太深**（级联太多加法/比较/多路选择）→ `T_comb_max` 大 → 只能降频或 **插流水线**。
- 这就是附件里「串起来也不能太长，可能超过一拍」的精确含义——不是「逻辑步骤太多写不下」，是 **物理延迟超出一个时钟周期**。

### 6.3 和软件的性能直觉

| 软件 | 硬件 |
|------|------|
| 慢循环 → 多跑几次 | 长组合路径 → 降 `clk` 或拆流水线 |
| 优化热点函数 | 优化 **关键路径** 或加寄存器切段 |
| profiling | 综合报告里的 **timing slack**、关键 path |

## 7. 流水线：把长路径切成多拍

若单拍内 `Fetch + Decode + Execute + Writeback` 全做完，组合逻辑太长 → 频率上不去。

**流水线**：在中间 **多插几级 FF**，每拍只做一小段：

```text
无流水（单周期）：  [ Fetch+Decode+Execute+WB ]  ← 一拍内全做完，路径长

三级流水（tiny-riscv）： 
  拍1: Fetch
  拍2: Decode        ← 级间 FF 锁 PC/IR/控制信号
  拍3: Execute
```

| 好处 | 代价 |
|------|------|
| 每拍组合逻辑变短 → **频率更高** | 指令 **latency** 变长（首条结果更晚出） |
| 吞吐可接近 **每拍一条**（理想情况） | 更多 FF、冒险处理（数据/控制 hazard，见 `04-riscv-core/01-pipeline`） |
| 面积与功耗上升 | 分支预测、冲刷等复杂度 |

GTM 类控制 IP 若逻辑简单，**状态机 + 单拍或两拍** 往往够用；做带 RV core 的 GTM 再认真定级数（tiny-riscv 选 **3 级 Fetch/Decode/Execute**，对标 Cortex-M3 量级）。

## 8. Verilog 写法：wire/reg 与 assign/always

### 8.1 module 里能放什么

RTL 文件的主体是 `module ... endmodule`。和 C 的「函数里才能写语句」类似，**过程语句**（`if` / `case` / `for` / 赋值等）只能写在 **过程块** 里，不能裸挂在 module 顶层。

骨架示例：

```verilog
module alu_demo (
    input  wire       clk,
    input  wire [1:0] op,
    input  wire [7:0] a, b,
    output wire [7:0] result
);
    // ① 声明
    reg [7:0] result_r;

    // ② 连续赋值（组合）
  // assign result = a + b;

    // ③ 过程块（组合或时序）
    always @(*) begin
        case (op)
            2'b00: result_r = a + b;
            2'b01: result_r = a - b;
            default: result_r = 8'd0;
        endcase
    end
    assign result = result_r;

    // ④ 子模块例化
    // other_sub u_other (...);

endmodule
```

**module 顶层常见合法内容**：

| 类别 | 例子 | 说明 |
|------|------|------|
| 声明 | `wire` / `reg` / `parameter` | 信号、常量 |
| 连续赋值 | `assign y = a & b;` | 描述组合逻辑连线 |
| 过程块 | `always` / `initial` | 里面才能写 `if` / `case` / `=` / `<=` |
| 例化 | `sub_module u_sub (...);` | 调子模块 |
| 生成 | `generate` / `genvar` | 参数化、批量例化（初学可后看） |

**顶层不能直接写**（会语法错误或综合不过）：

```verilog
// 错：case 不能单独放在 module 里
case (op)
    2'b00: result = a + b;
    default: result = 8'd0;
endcase
```

`case` / `if` 是 **过程语句**，必须包在 `always @(*)`、`always @(posedge clk)`、`initial` 等块里：

```verilog
always @(*) begin          // 组合：@(*) 表示相关输入一变就重算
    case (op) ... endcase
end

always @(posedge clk) begin   // 时序：时钟沿（或复位沿）才执行
    if (!rst_n) q <= 0;
    else        q <= d;
end
```

和 C 对照：`switch (op) { ... }` 得写在函数体里，不能贴在 `.c` 文件最外层；Verilog 同理。

**两种描述组合逻辑的路**：

| 写法 | 适合 |
|------|------|
| `assign result = ...` 或三元 `? :` | 简单表达式 |
| `always @(*) begin case ... end` | 多分支译码、复杂 `if`/`case` |

SystemVerilog 里常写 `always_comb`，语义同 `always @(*)`，仍是 **过程块 + case**，不是裸 `case`。

### 8.2 `wire` 与 `reg`（初学简化版）

| 类型 | 典型用途 | 备注 |
|------|----------|------|
| `wire` | 组合逻辑连线、模块端口 | 像「一根线」，用 `assign` 或模块输出驱动 |
| `reg` | `always` 块里赋值的变量 | **不一定是 FF**；组合 `always` 里也是 `reg` 类型（历史语法） |

综合后：`always @(posedge clk)` 里的 `reg` → FF；组合 `always` / `assign` → 组合逻辑。

### 8.3 `assign` — 组合逻辑

适合简单表达式、连续赋值：

```verilog
assign sum = a + b;
assign sel = cond ? x : y;
```

### 8.4 `always` — 组合或时序

**时序（寄存器）**：

```verilog
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= 8'd0;
    else
        cnt <= cnt + 1'b1;
end
```

**组合**（必须放在 `always @(*)` 里；须覆盖所有分支，否则可能推断 Latch）：

```verilog
always @(*) begin
    case (op)
        2'b00: result = a + b;
        2'b01: result = a - b;
        default: result = 8'd0;   // 要有 default
    endcase
end
```

| 场景 | 推荐 |
|------|------|
| 简单一位/表达式 | `assign` |
| 复杂 `case` / 多分支 | `always @(*)` |
| 时钟沿更新状态 | `always @(posedge clk)` |

tiny-riscv 译码、执行阶段大量用组合 `always`，就是为可读性；你读其 `id_stage.v`、`ex_stage.v` 时可对照 §5 结构。

## 9. 软件工程师常踩的坑

### 9.1 无意 Latch

组合 `always` 里：

```verilog
// 坏：没 else，y 在 if 不成立时「保持」→ 综合成 Latch
always @(*) begin
    if (en)
        y = d;
end

// 好：每分支都赋值
always @(*) begin
    if (en)
        y = d;
    else
        y = 8'd0;
end
```

**规则**：组合 `always` 里，每个输出在 **所有分支** 都要有赋值（含 `default`）。

### 9.2 阻塞 `=` vs 非阻塞 `<=`

差别主要在 **仿真怎么更新变量**，不是「`=` 快、`<=` 慢」。单语句时波形常一样；**多寄存器互相依赖** 时才会分叉。

#### RHS / LHS 是什么

赋值语句写成：

```text
LHS  <=  RHS;     或     LHS  =  RHS;
 │          │
 │          └── Right-Hand Side：等号/箭头 **右边**，要算出来的「新数据从哪来」
 └── Left-Hand Side：等号/箭头 **左边**，**被写入** 的那个信号/寄存器
```

例子：

```verilog
a <= din;     // LHS = a（被改的），RHS = din（读出来的值）
b <= a;       // LHS = b，RHS = a（读 a 的当前/旧值，取决于阻塞还是非阻塞）
c = b + 1;    // LHS = c，RHS = b+1（先算出表达式）
```

记法：

| 缩写 | 英文 | 含义 | 直觉 |
|------|------|------|------|
| **LHS** | Left-Hand Side | 赋值 **左边** | 「写到谁」 |
| **RHS** | Right-Hand Side | 赋值 **右边** | 「从哪读 / 算什么」 |

仿真器处理一句赋值时总是：**先求 RHS 得到一个值，再决定何时把这个值写进 LHS**。`=` 和 `<=` 的差别只在 **「何时写进 LHS」**。

#### 同一 time step 里两种写法差在哪

「同一 time step」≈ 仿真里某一个时刻（例如某次 `posedge clk`）内，连续执行完当前 `always` 块里的语句。

| 赋值 | 仿真器行为（同一 time step 内） |
|------|----------------------------------|
| **`=` 阻塞** | 算完 **RHS** → **立刻** 更新 **LHS** → 再执行下一句（下一句若再读这个信号，已是新值） |
| **`<=` 非阻塞** | 先用当前值算完本块里各句的 **RHS**，只把「要写入的 LHS←新值」记入队列 → **本阶段语句都跑完** → 再 **统一** 更新各 **LHS** |

逐步对照（沿前 `a=11, b=22`，`din=88`）：

```verilog
// 阻塞 =
a = din;   // 1) RHS=din→88；立刻 LHS a←88。此时 a 已是 88
b = a;     // 2) RHS=a→读到 88；立刻 b←88
// 结束：a=88, b=88

// 非阻塞 <=
a <= din;  // 1) RHS=din→88；记下「稍后 a←88」，a 此刻仍是 11
b <= a;    // 2) RHS=a→仍读旧值 11；记下「稍后 b←11」
           // 3) 本块结束，统一提交：a←88, b←11
// 结束：a=88, b=11（移位/流水，而不是全被 din 盖掉）
```

**为何要对齐真实 FF**：同一 `clk` 沿上，硬件里所有触发器 **并行采样、同时更新**；不会「A 先改完，B 再读 A 的新值」。`<=` 就是在仿真里复现这种并行；时序块里用 `=` 会伪造顺序，和硅上不一致。

**移位寄存器对比**（须先有已知初值；仿真里 `reg` 默认是 `X`，无复位/`initial` 会一直红）：

```verilog
reg [7:0] r0, r1, r2;
reg [7:0] din;

// 正确：非阻塞 → 移位。复位后若 din=8'hDD、且上一拍 r0=AA,r1=BB,r2=CC，
// 本拍沿后：r0=DD, r1=AA, r2=BB
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        r0 <= 8'hAA;
        r1 <= 8'hBB;
        r2 <= 8'hCC;
    end else begin
        r2 <= r1;
        r1 <= r0;
        r0 <= din;
    end
end

// 错误：阻塞且「先写前级」→ 沿后三级都变成 din（例如全 DD）
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) begin
        r0 = 8'hAA;
        r1 = 8'hBB;
        r2 = 8'hCC;
    end else begin
        r0 = din;
        r1 = r0;   // 读到的已是新 din，不是沿前旧 r0
        r2 = r1;
    end
end
```

仿真最小激励（testbench，仅仿真用）：

```verilog
initial begin
    rst_n = 0;
    din   = 8'hDD;
    #20;
    rst_n = 1;     // 释放复位后再打若干 clk，对比 r0/r1/r2
end
```

若写成你练习里的 `a <= din; b <= a; c <= b;` 却 **没有** `rst_n`/`initial`，波形上 `a/b/c` 会是 `XX`：第一拍起 `din` 若已知，需多拍才能把已知值一路推进到 `c`；`din` 也是 `X` 则全程 `X`。

**交换两寄存器** 同理：`a <= b; b <= a;` 能交换；`a = b; b = a;` 会把两者都变成原 `b`（同样要先复位到已知值再观察）。

**实用铁律**：

| 场景 | 用什么 |
|------|--------|
| `always @(posedge clk)` 更新寄存器 | **`<=`** |
| `always @(*)` 组合逻辑 | **`=`** |
| testbench 激励 | 常用 `=` / `#delay`（不建模 FF） |

初学：**时序只用 `<=`，组合只用 `=`**；时序块里混用 `=` 易出 race。

> 文档里若见到 `q <= d @ posedge clk`，那是 **讲义伪代码**，等价于 `always @(posedge clk) q <= d;`，不能直接写进可综合 `.v`。

### 9.3 把 RTL 当 C 程序读

```verilog
// 看起来像「先加后乘」两步程序，实际是组合链
always @(*) begin
    t = a + b;
    y = t * c;
end
```

综合结果是 **加法器输出直连乘法器输入**，同一拍内算完，不是 CPU 跑两条语句。

### 9.4 复位

- **异步复位**：`always @(posedge clk or negedge rst_n)`，复位独立于 clk（注意复位释放的同步化）。
- **同步复位**：只在 `posedge clk` 里判断 `rst_n`。
- 抓波时 **先确认复位序列** 是否释放干净，再看功能波形。
- 仿真里无复位、无 `initial` 时，`reg` 初值为 **`X`**（波形红条/`XX`），属正常，不是非阻塞写错了。

### 9.5 `initial` / `#delay` 只用于仿真

测试平台里 `initial`、`#10` 可以；**可综合 RTL** 里不要依赖它们做功能逻辑。

## 10. 抓波与硅前验证：实用读法

你已有 VCS/FPGA 经验，把 RTL 和波形 **对齐** 即可。

### 10.1 先找时钟与复位

1. 确认 `clk` 频率/周期与预期一致。  
2. 看 `rst_n` 拉低时长、释放是否在 clk 沿附近（同步释放常见）。  
3. 复位期间各 FF 是否到了已知初态。

### 10.2 认「谁是谁的 D 和 Q」

在 RTL 里搜 `always @(posedge clk)`，每个 `<=` 左侧就是某 FF 的 Q，右侧是下一状态 D。  
波形里 **同一信号名** 在沿前是旧 Q，沿后是本次采样的 D。

### 10.3 组合信号

组合逻辑输出可能在沿 **附近** 抖动（glitch）；FF 只采沿上稳定值。  
若看到「中间信号乱、输出却对」，正常——看 **寄存器输入** 在 setup 窗口是否稳定。

### 10.4 读 CPU/总线类波形

| 层次 | 建议 |
|------|------|
| 流水线 | PC、IR、stage 有效位是否每拍推进 |
| 总线 | `valid/ready` 握手、地址/data 对齐（可对照 `05-bus-rtl`） |
| 异常/trap | PC 跳变、`mcause` 类 CSR 是否在特定沿更新 |

### 10.5 仿真 vs 综合

- 仿真：**行为模型**，零 delay 或 `#delay` 可选。  
- 综合+STA：**真实延迟**；频率以 timing 报告为准。  
- FPGA 上板：还涉及 IO 时序、时钟树；和纯 RTL 仿真可能有差异。

### 10.6 最小练习路径

1. 读 tiny-riscv 的 `pc_reg.v` + 一级流水寄存器 → 对照 §5 图。  
2. 对 `id_stage` 组合译码 `always @(*)` → 标出输入/输出，仿真里看译码结果是否组合跟随 IR 变化。  
3. 若有条件，改时钟周期做 gate-level 仿真，观察 **缩周期** 后是否出现 X / 错误（时序违例的表现）。

## 小结

- RTL 描述 **并行电路**，不是顺序程序；时钟沿把状态 **离散推进**。
- **D 触发器** 在沿上锁存，是「一拍」的边界；**组合逻辑** 在同一拍内算中间结果。
- 典型块：**FF → 组合逻辑 → FF**；组合太深则 **超一拍**，需降频或 **流水线**。
- `assign` 做简单组合；复杂分支用 `always @(*)` + `case`/`if`（`case` 不能裸写在 module 顶层）。
- `<=` 用沿前旧值、沿后一起更新（对齐多 FF 并行）；时序块用 `=` 会在仿真里伪造顺序。
- 抓波：先 clk/rst，再把每个 `<=` 对应到 FF 的 D/Q，组合信号看沿前是否稳定。
